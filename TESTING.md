# Проверка «ЛЕСНОЙ | График кухни»

## Результаты технической проверки

Проверено 16 ноября 2026 года:

- **31 проверка логики данных — успешно.** Календарь на границах года, високосного дня и перехода часов; JSON и localStorage; независимые недели; проверка импортируемых данных; восстановление повреждённого сохранения; запрет записи и переполнение хранилища. Импорт команды сохраняет ID и графики, обновляет телефоны, не стирает номер пустым полем, отклоняет неоднозначные записи и безопасно обрабатывает совпадения ID.
- **10 проверок PNG — успешно.** Рендер настоящим Canvas, декодирование PNG и сверка размеров; все строки до 200 сотрудников; жёлтые пятница и суббота; экспорт без телефонов; пустой график; переносы длинных подписей. Пример с 8 вымышленными сотрудниками — 2400 × 784 px — дополнительно просмотрен визуально. Для большой таблицы масштаб снижается до площади менее 15 Мп.
- **46 проверок интерфейса — успешно.** В jsdom 31.0.1 выполнены настоящие скрипты приложения: добавление и изменение сотрудников; назначение и сохранение смен после повторной загрузки; копирование недель и переход года; своя смена; вставка диапазона Excel; отмена; корректный и ошибочный импорт JSON; отказ хранилища; защита от перезаписи другой вкладкой. Нажатие «Скачать PNG» запустило настоящий Canvas-рендер, показало предпросмотр и ссылку загрузки; переключатель телефонов создал новое изображение. Также проверены предпросмотр команды, повторный импорт без дубликатов, сохранение смен, отмена, личная ссылка при загрузке и смене фрагмента, удаление фрагмента до предпросмотра, отсутствие сетевой отправки и отказ повреждённой ссылки.
- Дополнительно проверены открытие заполненной ячейки без перезаписи, удаление одной смены с отменой и восстановлением после перезагрузки, быстрое удаление, ручные часы и минуты, ночной интервал и его повторное использование, запрет одинакового или пустого времени и поведение при лимите вариантов смен без потери данных.
- Проверено оформление по Excel-образцу: объединённый заголовок, полные дни недели и даты, объединение названий цехов только в левой части, две половины времени в каждом дне, пустые незаполненные ячейки, белый фон, чёрная сетка и ярко-жёлтые пятница и суббота. PNG больше не содержит отдельных легенды и нижнего информационного блока; пиксели фона, сетки и жёлтых ячеек проверены на реальном изображении.
- Проверено восстановление команды по личной ссылке без потери смен, ID и выбранной недели; локальная копия команды и восстановление через меню; отмена и повреждённый список. При отсутствующем основном сохранении читается действующая резервная копия, неизменившиеся данные не перезаписывают предыдущую копию, а намеренно пустой график не заменяется автоматически.
- **9 проверок масштабирования — успешно.** Начальный общий вид, направление двухпальцевого жеста, масштаб относительно центра, ограничения и перемещение, изменение размера окна и содержимого, длинная таблица, колесо/трекпад, переход к ячейке с клавиатуры и отключение обработчиков. Интеграция проверяет кнопки масштаба без записи данных и блокировку случайного добавления смены после жеста. CSS разобран в DOM: страница неподвижна, отдельные sticky-смещения отключены, все части таблицы находятся в одной масштабируемой поверхности. Фактические жесты и вёрстка Safari на физическом устройстве в этой среде не проверены.
- Обновление вариантов смен проверено на старых сохранениях и импорте: кнопки 10–22, 11:30–23:30 и Р; старые используемые значения остаются в истории, повторный запуск не сбрасывает настройки. Обновление одного контакта проверено без изменения остальных телефонов, порядка сотрудников, цехов и недель; обновляется и локальная копия для восстановления. Новый телефон из запроса дополнительно проверен локально на реальном персональном списке, без отправки данных на сервер.
- Форматирование сохранённого номера с «+7» проверено при обычном запуске без личной ссылки, повторной загрузке, ручном вводе, старой ссылке контакта, импорте и восстановлении команды. Номер и локальная копия получают формат с «8», остальные номера и смены сохраняются; повторное открытие не перезаписывает резервную копию.
- Загрузка отдельной недели проверена по личной ссылке и JSON: заменяются только указанные строки и пустые дни, сохраняются телефоны, ID, порядок, другие недели и строки остальных сотрудников. Проверены новые ночные интервалы, повторное использование времени, отмена, пустой браузер и отказ неверных данных без частичных изменений. Персональные файлы не входят в публичную сборку.
- Проверены отдельные ячейки строк цехов: совместимость старых JSON, валидация, независимые недели, заполнение, ручное время, свой текст, удаление, отмена, повторное открытие, копирование недели без смен сотрудников, защита используемых вариантов и очистка при удалении цеха. Реальный PNG содержит значения строк цехов, включая длинные подписи и цех без сотрудников. Web Share вызван с единственным полем files и PNG-файлом; title/text/url отсутствуют. Фактическая отправка через приложение Telegram на iPhone не выполнялась.
- Проверена геометрия таблицы и PNG: имена 190 px, телефоны 120 px, левая часть 310 px; ширина ячеек дней сохранена, строки сотрудников уменьшены с 30 до 28 px, цехов — с 28 до 26 px. Размер шрифта заголовка, дней недели, цехов, ФИО, подписей колонок и времени увеличен на 1 px без изменения насыщенности. Canvas-образец просмотрен визуально.
- Синтаксис всех JavaScript-файлов и наличие локальных файлов, подключённых HTML, проверены.

Итого: **136 успешных автоматических проверок в 8 Node.js-наборах**: 96 недельных и 40 месячных. Для табеля проверены 12 сценариев данных и расчётов, 12 Excel/PNG, 8 закрепления и масштабирования, 8 интеграционных сценариев интерфейса. При экспорте формулы охватывают весь диапазон дней и вычитают черновики: заполнение ранее пустого дня в Excel также пересчитывает выплату. Последний прогон выполнен с jsdom 31.0.1 и @napi-rs/canvas 1.0.13.

Публикация GitHub Pages: `https://99jrzwn8pb-droid.github.io/lesnoy-kitchen-/`. Источник публикации — main, папка /(root), HTTPS. После обновления необходимо сверять доступность страницы и совпадение опубликованных файлов с проверенной сборкой.

Для недельного PNG использована тестовая библиотека `@napi-rs/canvas`; приложение использует встроенный Canvas браузера. Автоматический браузерный прогон не заменяет проверку физического устройства.

Состав команды отдельно сверен с присланным фото и уточнениями пользователя: 12 сотрудников, 6 групп, 12 телефонов. Персональный список и личная ссылка не входят в публичные исходники и общий архив. Исходный HTML не был доступен: точная сверка функций первой версии не выполнена.

## Ручная проверка на Mac и iPhone

Используйте тестовые имена и телефоны. Перед проверкой импорта сделайте резервную копию реальных данных, если они уже введены.

1. **Сотрудники и цехи.** Добавьте сотрудников в разные цехи. Измените имя, телефон и цех. Убедитесь, что строки появляются в нужных группах.
2. **Одна смена одним нажатием.** Выберите смену и нажмите на несколько ячеек. Проверьте очистку и отмену последнего действия.
3. **Изменение смены.** Отредактируйте доступную смену, назначьте её и проверьте название в таблице.
4. **Недели и даты.** Выберите дату в середине недели. Проверьте понедельник и воскресенье, затем переход через конец месяца и года. Пятница и суббота должны оставаться жёлтыми.
5. **Сохранение.** Назначьте разные смены двум сотрудникам на двух неделях. Перезагрузите страницу, затем закройте и снова откройте её тем же способом в том же браузере. Проверьте сотрудников, телефоны и обе недели. Сообщение о сохранении не должно показывать ошибку.
6. **Копирование.** Заполните неделю, перейдите на следующую и скопируйте предыдущую. Проверьте все семь дней и всех сотрудников. Попробуйте копирование на уже заполненную неделю и отмените подтверждение: данные не должны измениться.
7. **PNG целиком.** Создайте достаточно строк для вертикальной прокрутки. На iPhone прокрутите таблицу вправо. Экспортируйте PNG и откройте полученный файл. В нём должны быть все сотрудники, все семь дней, верные даты, заголовок и жёлтые пятница/суббота, включая невидимые на экране части таблицы.
8. **Телефоны в PNG.** Сделайте экспорт с телефонами и без них. Проверьте оба изображения. Длинные имена и названия смен должны читаться.
9. **Отправка.** На iPhone сохраните PNG и прикрепите его в Telegram как файл. Убедитесь, что он открывается и текст читается при увеличении. Для теста используйте переписку с собой.
10. **Резервная копия.** Экспортируйте JSON с несколькими неделями. На другом устройстве или в отдельном тестовом профиле импортируйте его. Проверьте совпадение сотрудников, телефонов, цехов, смен и недель.
11. **Ошибочный импорт.** Попробуйте выбрать обычный текстовый файл или повреждённый JSON. Приложение должно объяснить ошибку и сохранить прежние данные.
12. **Независимость устройств.** Измените смену на Mac и убедитесь, что на iPhone она не меняется сама. Перенесите JSON вручную и проверьте замену данных.
13. **Узкий экран.** На iPhone проверьте сжимание и разведение двух пальцев, перемещение увеличенного листа, неподвижность страницы, кнопки масштаба, открытие и закрытие диалогов, ввод телефона, доступность кнопок при открытой клавиатуре и в горизонтальном положении.

### Месячный табель

Используйте только вымышленные данные. Проверьте табель на тестовой копии браузера, чтобы не затронуть рабочие записи.

1. Откройте **Месячный табель** → **Импорт Excel / JSON**, выберите тестовый `.xlsx`, проверьте предпросмотр и нажмите **Загрузить табель**. Убедитесь, что выбран правильный месяц, а недельный график остался прежним.
2. Проверьте быстрые значения **1**, **0,5**, **1,5**, **0**, стирание, редактирование заполненной ячейки, имени, должности и ставки, а также отмену последнего действия.
3. Сравните оплату: подтверждённые доли смен умножаются на ставку; черновики не учитываются. Для фиксированного оклада проверьте выплату за месяц без привязки к числу смен. Задайте ручную выплату, затем очистите её и проверьте возврат автоматического расчёта.
4. Измените профиль оплаты в текущем месяце и откройте будущий и прошлый месяц: профиль должен перейти в будущий месяц без изменения уже сохранённого прошлого.
5. Заполните часть месяца и импортируйте недельный график, пересекающий границу месяца. Проверьте, что существующие дни не заменились, пустые дни получили черновики, а даты соседнего месяца сохранились под соответствующим месяцем.
6. Проверьте закрепление заголовка и имён, отключение закрепления, перемещение и масштабирование на телефоне. Левая закреплённая часть не должна закрывать более примерно 45% экрана.
7. Экспортируйте Excel и проверьте, что файл открывается, содержит формулы итогов и закреплённые строки/столбцы. Экспортируйте PNG и проверьте, что он содержит полный табель; поделиться должен только PNG-файл. Проверьте также CSV и общую JSON-копию обеих таблиц.
8. Перезагрузите страницу и проверьте сохранение. Стирание данных сайта удаляет локальный табель, поэтому сначала восстановите данные из сохранённой JSON-копии.

В автоматизированной проверке использованы Chromium 151 и WebKit 26.5, настольный размер 1440×1000 и мобильный 390×844. Финальный прогон прошёл во всех четырёх сочетаниях браузера и размера экрана, включая редактирование, сохранение после перезагрузки, закрепление/масштабирование, Excel/JSON/PNG и возврат экспортированных файлов. Настоящий исходный Excel дополнительно импортирован в обоих браузерах и сравнен с независимым приватным расчётом: все строки, ставки, смены, выплаты и ФОТ совпали. В мобильном WebKit перемещение колесом проверяется DOM-событием: протокол Playwright не поддерживает колесо в этом режиме. Физический iPhone Safari и фактическая отправка через Telegram не проверялись.

## Для разработчика

Проверки логики данных находятся в `tests/core.test.cjs`. Запуск из папки проекта при установленном Node.js:

```sh
npm test
```

`npm test` запускает Node.js-наборы, включая jsdom. Для полного месячного браузерного прогона сначала запустите статический сервер на порту 8765, затем выполните команду ниже (требуются Python Playwright и установленные Chromium/WebKit):

```sh
npm run test:browser
```

Для локального просмотра сайта запустите статический сервер:

```sh
python -m http.server 8765 --directory site
```

Затем откройте `http://localhost:8765`. Для использования приложения сервер разработчика не требуется: сайт остаётся статическим.

Для всех технических проверок рекомендуется Node.js 24 LTS (24.15 или новее). Выполните `npm install`, затем `npm test`; для браузерного прогона установите Python Playwright и браузеры Chromium/WebKit. Зависимости нужны только для тестов; папку `node_modules` публиковать не надо. Архив для пользователей содержит содержимое `site`.
